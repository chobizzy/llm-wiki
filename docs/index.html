Compile once, not on every question

Most "chat with your notes" tools retrieve at question time: you ask, a retriever grabs some chunks, a model improvises, and nothing is learned. Ask again tomorrow and the same work happens again.

llm-wiki inverts that. Knowledge is compiled once, when a source arrives, into small linked markdown pages you can read yourself. Your sources are the source code. Your agents are the compiler. The wiki is the build artifact — and Obsidian is the IDE you browse it in.

The hard part isn't the compiling; it's keeping a compiler honest across many sessions and more than one agent. So the vault ships with a constitution.

Three layers

Sources stay untouched. The wiki is generated. The schema governs both.

Layer 1 · Sources

PDFs, articles, papers, chat exports, images. Immutable ground truth — agents read them and never write back.

Layer 2 · The Wiki

Small linked pages with frontmatter and inline provenance. The compiled artifact you actually browse.

Layer 3 · The Schema

AGENTS.md, 32 skills, and a CLI gate. How the whole thing stays honest over time.

Laws, not tips

Prompt-time instructions don't survive across sessions, models, or agents. A file in the repo does. Every vault carries an AGENTS.md each skill must read — versioned with your knowledge, and greppable. A sample of the eleven:

  1. Never delete a wiki page. Supersede it, and link the successor.
  2. Never modify anything in _inbox/. Sources are immutable ground truth.
  3. Never present a synthesized claim as extracted. Mark it ^[inferred] or ^[ambiguous].
  4. Never create a page for a concept that already has one. Merge instead.
  5. Never set lifecycle above draft on pages you write. Review is human-only.

An operation is done only when six conditions hold — pages, manifest, log, hot list, index, and commit — and then the gate runs: doctor must pass and lint must report zero failures. The agent is explicitly forbidden from declaring done on its own assessment.

Get started

Python 3.10+, and an agent that reads skills. Nothing else to install.

git clone https://github.com/chobizzy/llm-wiki ~/Projects/llm-wiki
pip install -e ~/Projects/llm-wiki
llm-wiki setup --vault /path/to/your/vault

Then scaffold a vault and drop a paper into _inbox/:

cp -r ~/Projects/llm-wiki/vault-template ~/Documents/my-wiki
cd ~/Documents/my-wiki && git init && git add -A && git commit -m "init"
llm-wiki setup --vault .

Tell your agent "ingest my inbox" and read the pages it writes. Full documentation lives in the README.
